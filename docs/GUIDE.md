## 1. 考え方

このアプリは「会話アプリ」ではなく、**小説品質のロールプレイをチャットUIで表示する**ためのものです。
そのために2つの原則があります。

**時間と場所の真実はアプリが持ちます。** AIには絶対時刻を書かせません。
「午後六時を回った頃」のような描写をAIがするとシステムの時計とずれていくため、
プロンプトには「時刻を明示する必要はない。時間はシステムが管理している」と毎回伝えています。
代わりにアプリが毎ターン「いま何時でどこにいるか」を渡します。

**設定はロアブックが持ち、あらすじは出来事だけを持ちます。** 同じ事実を二箇所に置きません。
だから要約プロンプトには「人物の設定（容姿・口調・経歴）は要約に含めない」と明記しています。

## 2. 用語

| 用語 | 意味 |
|---|---|
| **世界（World）** | 世界観の単位。ロアブック・場所・暦・イベント・システムプロンプトを持つ |
| **キャラクター** | 世界に属する登場人物。長期記憶（メモリー）の対象 |
| **ペルソナ** | あなたの分身。世界をまたいで使い回せる |
| **シナリオ** | 開始状況のテンプレート。参加キャラ・初期ステート・冒頭文を持つ |
| **会話（チャット）** | シナリオから作られた会話の実体 |
| **ステート** | その会話の現在時刻・場所・天候・在席者 |
| **発話** | 応答の中の1話者分の塊。**1発話 = 1つの吹き出し** |
| **準レギュラー** | 毎回は同席しないが人物像を保持したいキャラ |

## 3. 最初のセットアップ

会話を始めるには **世界 → キャラクター → シナリオ** の順に作ります。

### 手順

1. **世界を作る**（チャット一覧の右上「本」アイコン → ＋）
   - 「世界のシステムプロンプト」に文体・世界観・許可される表現を書きます
   - 初回起動時は「ヴェイン古書店の世界」（場所10件＋暦）が自動で入っています

2. **場所を確認・追加する**（世界 → 場所）
   - IDは英小文字・数字・アンダースコアのみ（例 `vein_bookstore`）
   - **屋内**をONにすると、そこにいる間は天候をAIに伝えません
   - **エリア**が同じ店同士は、営業状況がお互いに見えるようになります（後述）

3. **キャラクターを作る**（世界 → キャラクターを追加）
   - 名前欄の左の丸枠から**アイコン画像**をアップロードできます
   - **別名**は呼称ゆれ対策です。「マーゴット・ケイン」を「マーゴット:」と書かれても
     同じ人物だと解釈できるようになります
   - **準レギュラー**をONにすると、参加者に入れなくても関連ロアが発火したターンだけ
     定義が読み込まれます

4. **ペルソナを作る**（チャット一覧の右上「人物カード」アイコン）
   - あなた自身の名前と説明です。ここの名前がAIへの送信時に自分の発言に付きます

5. **シナリオを作る**（世界 → シナリオを追加）
   - **参加キャラ**・**開始時刻**・**場所**・**在席キャラ**を決めます
   - **冒頭の応答文**は話者ラベル付きで書きます（例: `ナレーター: 午後の雨が窓を叩いている。`）

6. **会話を始める**（チャット一覧の右下＋ → シナリオを選ぶ）

> **重要:** シナリオの参加キャラ・ペルソナ・初期ステートは、**会話を作った時点でコピー**されます。
> あとからシナリオを編集しても、既にある会話には反映されません。反映したい場合は新しく会話を始めてください。
> 一方で、**ロアブック・場所・暦・イベント・キャラ定義は常に最新を参照**します。

## 4. 会話画面の使い方

### 画面の見方

- **ヘッダー**: 戻る／キャラ名とナレーターのON・OFF／**モデル切替ピル**
- **ステートバー**（帯）: 季節・曜日・時刻・場所・天候。**タップするとステート編集**へ。
  右の**時計アイコン**は「場面を進める」（6章）です
- **吹き出し**: セリフは通常サイズ、地の文は一段小さく淡い色で表示されます
- **ハートの行**: ナレーション（地の文）。吹き出しは付きません

### 操作

| 操作 | 場所 |
|---|---|
| 送信 | 右下の紙飛行機。Ctrl（⌘）+ Enter でも送れます |
| 停止 | 生成中は■に変わります。**そこまでの生成分は保存されます** |
| モデル切替 | ヘッダーのピル。会話ごとに保存されます |
| 再生成・編集・コピー・分岐・削除 | 吹き出し右の **⋯** |
| 候補の切替 | 再生成すると `‹ 2/3 ›` が出ます |
| オートプレイ・あらすじ・プロンプト確認・書き出し | 左下の **＋** |

### ⋯メニューの使い分け

- **再生成**: 同じ場面をもう一度書かせて候補を増やします。**最後の応答にだけ**使えます
- **ここから分岐**: そのメッセージまでをコピーした新しい会話を作ります。
  過去のメッセージをやり直したいときはこれを使います
- **編集**: 本文だけを直します。**時刻や場所は変わりません**
  （内容とステートがずれたらステート編集で直してください）

> **なぜ過去のメッセージは再生成できないのか:** このアプリは各メッセージに
> 「その時点の時刻・場所・在席者」のスナップショットを持たせています。過去を差し替えると
> それ以降の記録と矛盾するため、過去へのやり直しは分岐に統一しています。

### オートプレイ

＋メニューから起動します。あなたの入力なしで場面が進みます。

- 上限は **3ターン**（`autoplay_steps`）
- **継続判定**がONなら、区切りが良いとAIが判断した時点で自動停止します
- ■ボタンでいつでも止められます

## 5. ★ 発火条件のまとめ

ここが一番わかりにくいところなので、機能ごとに「いつ動くか」を整理します。

### 5-1. ロアブック

**そのターンの話題に関係する世界設定だけを読み込ませる**仕組みです。

#### 一覧の見方

- **カテゴリ**と**ON / OFF** で絞り込めます。2つは掛け合わさります（例: 「人物」かつ「OFF」）
- 発火キーワードは先頭3語と残りの件数（`+6`）を出します。全部見るにはエントリを開いてください
- 発火キーワードの編集は**1語ずつのチップ**です。読点・カンマ・Enter で確定し、× で消せます

#### 手順1: 対象になるか（スコープ）

以下を**すべて**満たすエントリだけが判定の対象になります。

- その世界のエントリである
- **有効**がONである
- **対象キャラ**が未指定、または対象キャラが参加キャラ（準レギュラー含む）である

#### 手順2: 発火するか（以下のどれか1つでも満たせば発火）

| 種類 | 条件 |
|---|---|
| **常時** | 「常時注入」がON。毎ターン必ず発火します |
| **場所** | 場所トリガーに**現在地**が含まれる |
| **季節** | 季節トリガーに**現在の季節**が含まれる |
| **キーワード** | キーワードのどれかが**直近8件**のメッセージ本文に含まれる |

- キーワードは**大文字小文字を区別しない部分一致**です。単語の区切りは見ません
  （「港」は「空港」にも反応します）
- 走査対象の8件（`lore_scan_window`）には**いま送ったあなたのメッセージも含まれます**。
  なので言及したその場で発火します
- **あらすじは走査されません**

> **場所・季節トリガーがある理由:** キーワードだけだと「カフェに入る」と書いた次のターンに
> ようやくカフェのロアが乗る、という1ターンの遅れが出ます。場所トリガーを付けておけば
> 入ったターンから乗ります。

#### 手順3: 連鎖するか（再帰走査）

`lore_recursion` が2以上のとき、発火したロアの**本文の中の語**も次の走査対象に加えて連鎖を辿ります。
新しい発火がなくなった時点で打ち切ります。既定は1（連鎖なし）。

> 常時・場所・季節の判定は最初の1回だけです。連鎖するのはキーワード発火のみです。

#### 手順4: 実際に載るか（予算）

発火したエントリを次の順に並べて、上から **12,000文字**（`lore_budget_chars`）に
収まるまで採用します。

1. 常時
2. 場所・季節による発火
3. キーワードによる発火

（同じ順位の中では**優先度が大きい順**、それも同じならID順）

- **常時のエントリは文字数に数えますが、絶対に落としません**
  （常時だけで予算を超える構成は設定ミスとして扱います）
- 溢れた分はそのターンだけ載りません。次のターンにまた判定されます

#### 確認方法

＋メニューの**「プロンプトを確認」**で、そのターンの
**発火 / 採用 / 予算超過で落ちた**の3区分が見られます。思ったように出ないときはここを見てください。

### 5-2. 条件付きイベント（世界 → イベント）

条件を満たしたときに、ロアブックとは別枠で一文を注入します。

> **実際に作るときは [`EVENTS.md`](EVENTS.md) を見てください。**
> JSONの書き方、フェーズ0→4の完全な設計例、デバッグ手順が載っています。

> **v1.5.3 で判定のタイミングが変わりました。**
> 以前は「送信 → 判定 → そのターンのプロンプトに注入」でしたが、
> 現在は **AIの応答が完了して時刻・場所が確定した直後**に判定し、
> 注入は**次のターン**に載ります。
> 「カフェに着いた」という応答が返ってから、次のターンで「店内は混んでいる」が効く、という順番です。
> 途中で停止した応答では判定しません（発火の取りこぼしではなく、意図的な仕様です）。

#### 判定の流れ（上から順に、1つでも落ちたらそのイベントは見送り）

| # | 段階 | 内容 |
|---|---|---|
| 1 | **有効か** | イベントのスイッチがON、かつその会話でイベント機能がON |
| 2 | **条件（`when`）** | 下の条件式を満たすか |
| 3 | **チェック方式（`check`）** | 毎ターン／条件を満たした瞬間だけ／日が変わった時だけ／場所が変わった時だけ |
| 4 | **トリガー** | 同じスコープで発火済みでないか（下表） |
| 5 | **確率（`chance`）** | 抽選に当たるか。シード固定なので**再生成しても結果は変わりません** |
| 6 | **上限** | 優先度の高い順に、1ターン最大2件（設定で変更可）。演出指示は**常に1件まで** |

各イベントが何段階目で落ちたかは、世界 → イベント の **「最新のチャットで評価」** で確認できます。

#### 条件式（`when`）

JSONで書きます。**同じ階層に並べた項目はAND**、**配列で並べた値はOR**です。
`all` / `any` / `not` で入れ子にできます。

| 項目 | 意味 | 例 |
|---|---|---|
| `season` | 季節 | `"秋"` |
| `month` | 月 | `9` または `[9, 10]` |
| `week` | 月内の週（1〜4） | `4` |
| `weekday` | 曜日 | `"土"` |
| `time_after` | この時刻以降 | `"17:00"` |
| `time_before` | この時刻より前 | `"23:00"` |
| `location` | 場所ID | `"main_street"` |
| `location_area` | エリア | `"center"` |
| `weather` | 天候 | `"雨"` または `["雨", "雪"]` |
| `present_has` | この人がいる | `"toby"` |
| `present_lacks` | この人がいない | `"toby"` |
| `var` + 比較子 | 進行フラグ（5-9） | `{ "var": "case_phase", "gte": 2 }` |

`var` の比較子は `eq` / `ne` / `in` / `gt` / `gte` / `lt` / `lte` です。比較子を書かないと「真であること」の判定になります。

```json
{
  "all": [
    { "month": 9, "week": 4 },
    { "time_after": "17:00" },
    { "any": [{ "weather": ["雨", "雪"] }, { "var": "case_phase", "gte": 2 }] },
    { "not": { "present_has": "toby" } }
  ]
}
```

> **季節ではなく月＋週を使ってください。** 秋は7〜9月の3ヶ月あるので、`season: "秋"` だと
> 初秋にも発火してしまいます。単日〜単週のイベントは `month` + `week` で指定します。

> 場所メモ（「駅前のベンチ」など自由入力）を使っている間は、`location` / `location_area` は
> **常に偽**になります。エリアが導出できないためです。

#### チェック方式（`check`）

| 種類 | 動作 | 向いている用途 |
|---|---|---|
| **毎ターン** | 条件を満たす限り毎回判定する | 天候や時間帯の演出 |
| **条件を満たした瞬間** | 前ターンは偽、今ターンは真、のときだけ | 入店・初対面など「〜した瞬間」 |
| **日が変わった時** | 日付が進んだターンだけ判定する | 朝の日課 |
| **場所が変わった時** | 場所が変わったターンだけ判定する | 到着時の描写 |

#### トリガー（繰り返し方）

| 種類 | 同じ〇〇では1回だけ |
|---|---|
| **一度きり** | その会話で1回 |
| **1日1回** | ゲーム内の同じ日 |
| **1訪問1回** | 同じ場所に滞在している間 |
| **フェーズごと1回** | 指定した進行フラグの値が同じ間（`trigger_var` で指定） |
| **年に一度** | ゲーム内の同じ年 |
| **クールダウン** | 前回からゲーム内で指定日数 |
| **繰り返し** | 制限なし（履歴を見ない） |

- 発火の記録は**会話ごと**です。別の会話では改めて発火します
- **再生成すると、その応答の発火記録を消してから判定し直します**。一度きりのイベントも、作り直した応答で改めて発火し得ます
- **分岐（fork）は分岐点までの発火記録を引き継ぎます**。分岐先で同じイベントが二重に起きることはありません
- 誤って発火した記録は、⋯ → ステート編集 の「発火履歴」から1件ずつ取り消せます

#### 注入は「次の1ターンだけ」

発火したイベントの文が載るのは、**発火した次の1ターンのみ**です。その次のターンでは消えます。

```
ターン1  条件を満たす応答が返る → このターンの終わりに発火
ターン2  イベントの文が載る
ターン3  もう載らない
```

**「この場面のあいだずっと」効かせたい場合、一度きりのイベントでは足りません。**
たとえば `check: 条件を満たした瞬間` ＋ `trigger: 一度きり` で
「初対面らしく書くこと」を注入しても、効くのは**出会った次の1ターンだけ**で、
初対面の会話の残りには載りません。

場面のあいだ持続させるには、次のどれかを使ってください。

| やり方 | 使い方 |
|---|---|
| **`trigger: 繰り返し` ＋ `check: 毎ターン`** | 条件が真であるあいだ毎ターン載る。天候・時間帯・場所など、状態そのものが条件になるとき |
| **進行フラグと組み合わせる** | 「瞬間」のイベントが `set_vars` でフラグを立て、別の「繰り返し＋毎ターン」のイベントが `{ "var": "そのフラグ" }` を条件に毎ターン注入する。場面が終わったらフラグを下ろす |
| **ロアブック** | 常時注入・場所トリガーで持続的な文脈を渡す。イベントは「起きたこと」、ロアは「ずっとそうであること」と分けると整理しやすいです |

> 進行フラグを使うやり方が、いちばん融通が利きます。
> 「初対面」フラグを立て → そのあいだ演出指示を毎ターン注入 → 別れる／次の段階に進んだら下ろす、
> という形にすれば、開始と終了を自分で決められます。

#### 注入のされ方（`inject_mode`）

| 種類 | 置かれる場所 | 意味 |
|---|---|---|
| **事実** | `# 発生中の出来事` | 「そういう状況である」と伝えるだけ |
| **演出指示** | `# 今回の演出指示` | 「こう書け」と指示する。**1ターン1件まで** |

システムプロンプト末尾のブロック順は
`# 現在の状況` → `# 進行状況` → `# 発生中の出来事` → `# 今回の演出指示` です。

#### 進行フラグの書き換え（`set_vars`）

イベントは発火と同時に進行フラグを書き換えられます。物語を次の段階へ進めるのはこの仕組みです。

```json
[{ "key": "case_phase", "op": "set", "value": 2 }]
```

`op` は `set`（代入）と `add`（加算、数値のみ）です。
AIが触れない `system_only` のフラグも、**イベント経由なら**書き換えられます。

### 5-3. 要約（あらすじ）

> **あらすじが冗長に感じたら、設定 → Summary & Memory の「要約の方針」を見てください。**
> 「何を落とすか」に項目を足すのが一番効きます。落とす基準が無いと、短くする方法が
> 文を詰めることしか無くなり、接続詞で繋いだ列挙になります。
> 前回分との統合・人物設定を書かないこと・日付・文字数はアプリ側が必ず付けるので、
> ここに書く必要はありません。「既定に戻す」でいつでも戻せます。

長くなった会話を折りたたんで、古い出来事を保ちながらコンテキストを節約します。

| 項目 | 動作 |
|---|---|
| **いつ発火するか** | 応答を保存した直後、**未要約のメッセージが32件**（`summary_interval`）以上のとき |
| **何を要約するか** | 未要約分のうち、**直近を除いた**範囲。直近は最大24件（未要約数−2、最低1件）残します |
| **どう書き直すか** | **前回のあらすじ＋今回の範囲**をモデルに渡し、統合した1本に書き直させます |
| **長さ** | 全体で500文字程度（`summary_max_chars`） |

- 前回分を捨てて新しい分だけ要約する方式ではないので、**古い出来事が消えません**
- 要約されたメッセージは、以降AIに渡す履歴から外れます（画面には残ります）
- 各出来事には**ゲーム内日付が添えられます**（「昨日」などの相対表現がずれないように）
- ＋メニュー → あらすじ から、手動での実行・編集・削除ができます

### 5-4. メモリー（キャラの長期記憶）

一覧では本文を3行まで表示します。**行をタップすると編集**（内容・対象・ピン留め・削除）でき、
ピン留めだけは行の左のボタンから直接切り替えられます。ピン留めしたものは一覧の先頭に集まります。

会話をまたいで覚えておく事実です。キャラクター編集 → 脳アイコンから登録します。

#### 注入条件

| 対象タグ | いつ載るか |
|---|---|
| **空** | 常に載る |
| **人物IDを指定** | その人物が**在席中**、または**その人物に紐づくロアが発火した**ターンだけ |

> 対象タグを使うと、登場人物が増えても文脈が濁りません。
> 「トビーについての記憶」はトビーが居るときだけ読ませる、という使い方です。

#### 保存される条件

自動抽出は、次を**すべて**満たすものだけを保存します。

1. 数シーン後にも有効である
2. 将来の会話・判断・行動へ影響する
3. 忘れると明確な矛盾または不自然さが生じる
4. 単なる動作、一時的な感情、その場限りの雑談ではない
5. 既存の記憶と重複しない

**該当なしが普通です。** 1件も保存されないターンのほうが多くて正常です。

#### 自動で走ったときは結果が画面下に出ます

自動要約・自動抽出はAIの応答のあとに裏で走るので、成否が分かるように
**画面下部のメッセージ**でお知らせします。

| 出るもの | 意味 |
|---|---|
| `12件を要約しました（480文字）` | 成功 |
| `メモリーを2件保存しました` | 成功 |
| `メモリー: 12件を見ましたが、保存に値する内容はありませんでした` | 成功（該当なし） |
| 赤い `要約に失敗しました: …` | **失敗。** 理由が続けて出ます |
| 赤い `メモリーの抽出に失敗しました: …` | **失敗。** 理由が続けて出ます |

走らなかったターンでは何も出ません（毎ターン出ると邪魔なので）。
失敗した場合、要約は保存されず、抽出はその範囲を保留するので、
設定 → Summary & Memory の「要約・抽出のモデル」を変えれば拾い直せます。

#### 「保存に値する内容はありませんでした」と出たら

**下に赤い説明が出ていないか確認してください。** 出ていればそれは失敗であって、
「該当なし」ではありません。

| 説明 | 対処 |
|---|---|
| モデルが空の応答を返しました | 設定 → Summary & Memory の「要約・抽出のモデル」を変える |
| 応答が長さの上限で切れました | 同じくモデルを変えるか、対象の会話が長すぎないか確認する |
| モデルが拒否しました | 会話の内容をモデルが扱えていません。モデルを変える |

**失敗した範囲は保留されるので、設定を直せば拾い直せます。**

#### 何が保存されるか試す・そのまま保存する

会話の ＋ → **「メモリー候補を確認」**で、**保存せずに**候補と理由だけ見られます。
条件に合わないものが拾われていないかを、実際に保存する前に確かめられます。

内容がよければ、そのまま **「◯件を保存」** で保存できます。
**表示されているものがそのまま保存される**ので、抽出をやり直しません（AIの呼び出しも増えません）。
保存すると、その範囲は抽出済みになります。

> 自動抽出が失敗したとき（OpenRouterのクレジット切れなど）の立て直しにも使えます。
> クレジットを足してから「メモリー候補を確認」→「保存」で、失敗した範囲を拾い直せます。

#### 自動抽出

設定の**自動抽出**をONにすると、要約が走ったタイミングで会話から記憶候補を自動で拾います。
既定はOFFです（トークンを消費するため）。抽出は要約・抽出用の軽量モデルで行われます。

#### いつの出来事か（日付）

自動で拾った記憶には、**現実の日時ではなくゲーム内の日付**が入ります。
一覧では `3年8月10日` のように、AIに渡すときは現在時刻から見て
`(3日前) 港で待ち合わせると約束した` のように相対表記で載ります。

- 手で足した記憶と、この機能より前に保存された記憶は**日付なし**です。
  現実の日時からゲーム内の日付は逆算できないので、推測では埋めません
- 日付なしの記憶は今までどおり日付を付けずに渡されます。動作は変わりません
- 記憶はキャラクターに紐づくので、同じ世界の別の会話が別の日付にいることがあります。
  相対表記が意味を持たない場合は自動で絶対日付に切り替わります

### 5-5. 天候

**日付が変わったタイミングでのみ抽選**し、その日は固定します。

- 抽選表は世界ごとに編集できます（世界 → 暦・天候）
- 既定の重み: 春は霧40/雨30/曇20/晴10、夏と秋は晴50/曇30/雨20、
  冬は雨30/みぞれ25/曇25/雪10/晴10
- 日付が変わったターンは、状況ブロックに
  「日付が変わり、天候は◯◯になった」の一文が添えられます

> ターンごとに抽選すると晴れと雨が数ターンで往復してしまうため、日単位で固定しています。

**屋内にいるときは天候をAIに伝えません**（場所の「屋内」設定）。

---

### 5-6. 営業時間

> **時刻は「9:00」「09：00」（全角）「900」「9時」のどれでも入力できます。**
> 入力欄の下に「9:00 として保存します」と出るので、意図どおりか確認できます。

現在地と**同じエリア**にある店の営業状況を、状況ブロックに載せます。

> **エリアは世界ごとに決められます。** 場所の画面の右上（鉛筆）から、表示名の変更・並び替え・
> 追加・削除ができます。新しい世界には8つ入っています（丘の上／中央／裏通り／港／郊外／
> 市場／住宅区／地下）。
> **表示名はいつでも変えられますが、IDは作成後は変えられません。** 場所とイベントの条件が
> IDで参照しているためで、変えられてしまうと条件が黙って発火しなくなります。
> 場所に使われているエリアは削除できません（先に場所のエリアを変えてください）。

#### 載る条件

- 現在地にエリアが設定されている
- 同じエリアに、**開店・閉店の両方**が設定された別の場所がある
- 場所メモ（未登録地）を使っていない

```
〈無銘〉は営業中。〈マルロウ〉は閉店済み。
```

- 状態は **営業中 / 開店前 / 閉店済み** の3つです
- 閉店が翌日にまたがる店は `26:00` のように24時超で指定します（深夜営業の判定が正しく働きます）

---

### 5-7. 終電（呼び方は変えられます）

> **鉄道が無い世界観なら、世界 → 暦・天候 からオフにできます。**
> 呼び方も「最終バス」「最終転移」などに変えられ、通知文と終電後の文の両方に反映されます。


**通知窓の中でだけ**表示します。毎ターン残り時間を見せると、夕方から
「そろそろ帰らないと」の描写が出続けてしまうためです。

| 時間帯 | 表示 |
|---|---|
| 終電の**60分前**〜終電まで | 「終電まで残り◯分。」 |
| 終電後 〜 **翌日の日の出**まで | 「終電は終了。帰りは徒歩か辻馬車になる。」 |
| それ以外 | 何も出しません |

既定の終電は23:00。通知開始（60分前）と終電後の文面は世界ごとに変えられます（世界 → 暦・天候）。

---

### 5-8. 準レギュラーの定義

キャラクターの「準レギュラー」をONにすると、**参加者に入れなくても**
そのキャラに紐づくロアが発火したターンだけ、人物定義がプロンプトに読み込まれます。

会話に必要ないときは載らないので、常連ではない人物像を何人でも保持しておけます。

### 5-9. 進行フラグ（物語の段階）

「事件がどこまで進んだか」「もう会ったか」といった**物語の状態**を、会話ごとに数値・真偽値・短い文字列で持ちます。
時刻や場所と同じく、アプリ側が管理してプロンプトに載せます。

#### 定義する（世界 → 進行フラグ）

世界ごとに**使えるキーを先に定義**します。ここに無いキーはAIもイベントも書き込めません（誤字で勝手に増えるのを防ぐため）。

| 項目 | 意味 |
|---|---|
| **キー** | `case_phase` のような英数字の識別子 |
| **型** | 数値 / 真偽 / 短い文字列（32文字まで） |
| **初期値** | 会話を始めたときの値 |
| **範囲** | 数値の下限・上限。外れた値は丸めます |
| **後戻りしない** | ONにすると、今より小さい値への変更を捨てます |
| **更新できるのは** | 「AIも可」か「システムのみ」（＝AIは触れず、イベントと手動編集だけ） |
| **フェーズ** | 数値ごとの名前・公開状況・裏メモ |

#### フェーズの「公開状況」と「裏メモ」

- **公開状況**はプロンプトの `# 進行状況` ブロックに載ります
- **裏メモ**は**絶対にプロンプトへ載りません**。あなたが構成を見失わないためのメモ欄です

#### 更新のされ方

| 経路 | system_only のキー | 範囲外 | 後戻り |
|---|---|---|---|
| **AI**（応答末尾の `set_var:`） | 無視（警告が出ます） | 丸める | 捨てる |
| **イベントの `set_vars`** | 更新できる | 丸める | 捨てる |
| **手動編集**（⋯ → ステート編集） | 更新できる | 丸める | **通る**（救済手段） |

進行が詰まったとき（AIがフラグを上げてくれない、上げすぎた）は、ステート編集から直接直してください。

#### 遷移漏れのチェック

世界 → イベント の画面に、**どのフェーズへも進む手段が無い**場合は警告が出ます。
「フェーズ3を作ったのに、3にする `set_vars` を持つイベントが1つも無い」といった作り忘れを見つけるためのものです。

#### 有効・無効

イベントと進行フラグは、**設定 → 会話ごと**の順に上書きできます。
会話の ＋ → 「この会話の設定」で「継承 / ON / OFF」を選びます。
OFFにすると、進行状況ブロックも `set_var` の指示も出さず、`var` を使った条件は常に偽になります。

## 6. 時間・場所・天候の仕組み

### 時間の進み方

AIは応答のたびに「この場面で何分経過したか」を返します。会話だけなら5〜15分、
移動や場面転換があれば実際の所要時間です。それをアプリが現在時刻に足します。

- **1ヶ月28日・1年12ヶ月**（＝336日）が既定です。だから週は常に第1〜第4週になります
- 曜日・季節・日の出・日没はすべて時刻から計算されます
- 日の出・日没は月ごとの表から求め、書いていない月は**前後の月から補間**します

### 場所の扱い

AIが場所IDの一覧から選んで返します。**一覧にない場所**（「路地裏」「橋の上」など）に
移動した場合は、`場所メモ` に文字列として退避され、登録済みの場所は変わりません。

- 場所メモが入っている間は、営業時間の判定はスキップされます
- 登録済みの場所に戻ると場所メモは自動で消えます
- 場所メモはステート編集画面から手動で編集・クリアできます

### 同行者

**場所が変わっても在席者は維持されます。**「二人で店を出る」が最も多いパターンなので、
同行して移動したものとして扱います。別れる場合はAIが明示的に退出を書きます。

### 場面を進める（天候とイベントを動かしたいとき）

ステートバーの**時計アイコン**から開きます。ステート編集で日付を書き換えるのとは
別物で、こちらは**AIが1ターン進めたときとまったく同じ扱い**になります。

| | ステート編集（鉛筆） | 場面を進める（時計） |
|---|---|---|
| 値を直す | ○ | 時刻と場所だけ |
| 巻き戻す | ○ | ×（前にだけ進む） |
| 日付が変わったとき天候を引き直す | × | ○ |
| イベントの判定 | × | ○ |
| AIの呼び出し | なし | なし |

`+30分` `+1時間` `+3時間` `翌朝 8:00` `翌日の同じ時刻` のボタンか、年月日時分の直接指定で進めます。
会話には `――秋・第2週の水曜日 08:00、古書店。` のような**区切り線**が入り、
AIから見ても場面が変わったことが分かる形になります。区切り線の右のゴミ箱で取り消せます
（時刻もイベントの発火も一緒に戻ります）。

> 「翌日の朝から始めたい」ときは、ステート編集で日付を書き換えるのではなく
> こちらを使ってください。書き換えでは天気が前日のまま固定され、
> 朝にだけ起きるイベントも判定されません。

複数日をまとめて進めた場合、天候の抽選も「日が変わったとき」のイベント判定も**1回だけ**です。

### ステートがずれたら

ステートバーをタップすると編集画面が開き、**時刻・場所・場所メモ・天候・在席者**を
すべて手で直せます。AIが場所や時刻を取り違えたまま数ターン進むことは必ず起きるので、
気づいたらここで直してください。

**本文に「16時を回った」と書いてあるのに時刻が14:00のまま**、ということも起きます。
経過分はAIが自己申告した数字で、本文とは独立に書かれるためです。
少しのズレなら時計アイコンの `+30分` `+1時間` で合わせるのが手早く、
大きくずれたときはステート編集で直してください。

同じ画面の下部で、各ターンにAIが返した**生の差分ログ**も確認できます。

### ⚠ +Xh バッジ

1回の応答で**24時間以上**進んだ場合、ステートバーに `+Xh` のバッジが出ます。
AIが経過時間を大きく誤ったサインなので、タップしてステート編集で直してください。

## 7. 話者の書き方

シナリオの**冒頭の応答文**や、キャラの**口調例**を書くときの形式です。

```
ナレーター: 午後の雨が窓を叩いている。棚の奥から、紙と埃の匂いが濃く立ちのぼった。
アシュリー: 本を閉じ、薄紫の瞳が入口へ向く。
「おや。……濡れましたね。拭くものを出しましょうか」
NPC[店主]: 「らっしゃい」
```

### ルール

- 行頭に **「話者名: 」** を置きます。コロンの後のスペースは省略可、全角コロンも使えます
- **セリフは「」で囲み、それ以外は地の文**として書きます
- 動作・表情・地の文・セリフは1つの発話にまとめて構いません（段落で分けても1つの吹き出しになります）
- `*` や `_` で地の文を囲まないでください
- **地の文だけの行**は `ナレーター: ` で始めます
- **その場限りの脇役**は `NPC[短い名前]: ` の形式です。登録済みの人物にこれを使ってはいけません

### 話者の判定順

サーバ側で次の優先順に判定します。

1. 参加キャラの名前または別名と一致 → そのキャラ
2. ペルソナ名と一致 → あなた（本来出ないはずなので警告が出ます）
3. 「ナレーター」と完全一致 → ナレーション
4. 準レギュラーの名前または別名と一致 → そのキャラ（参加者への追加を提案します）
5. `NPC[名前]` の形式 → その場限りの脇役
6. どれにも当てはまらない → **直前の発話に連結**され、警告が出ます

最後に、**連続する同じ話者の発話は1つにまとめます**（間に別の話者が入る場合はまとめません）。

## 9. 困ったとき

### 期待したロアが出ない

＋メニュー →「プロンプトを確認」で発火状況を見てください。

| 症状 | 原因と対処 |
|---|---|
| 発火にも出ていない | 「有効」がOFF／対象キャラが参加していない／キーワードが直近8件に出ていない |
| 発火しているが採用されていない | 予算（12000文字）超過。優先度を上げるか、常時に切り替える |
| 話題を変えても古いロアが残る | 走査窓（8件）から抜けるまで数ターンかかります |

### 時刻や場所がおかしい

ステートバーをタップして直してください。AIには時刻を書かせない指示を入れていますが、
経過時間の見積もりを誤ることはあります。`+Xh` バッジが出ていたら要注意です。

### 日付を進めたのに天気が変わらない／朝のイベントが起きない

ステート編集で日付を書き換えただけだと、天候の抽選もイベント判定も走りません
（「値を直す」ための経路なので、意図的にそうしています）。
ステートバーの**時計アイコン**の「場面を進める」を使ってください（6章）。

### 「ステート差分が3回連続で欠落しています」と出る

応答の末尾に状態の差分を書かせる形式に、そのモデルが従えていません。
設定 → State → 抽出方式を「**別コールで抽出**」に変えてください。

### 「他の端末で生成中です」と出る

同じ会話に対して別の端末から同時に生成しようとしています。片方の完了を待ってください。

### 生成が途中で止まった／失敗した

- **停止した場合**: そこまでの分は保存されます。**ゲーム内時間は進みません**。
  続きが欲しいときは⋯から再生成してください
- **失敗した場合**: あなたの発言だけが残ります。画面に出る「応答を再試行」を押してください
  （同じ発言が二重に保存されることはありません）

### バックアップしたい

サーバの `data/app.sqlite` を1ファイルコピーするだけです。アイコン画像もこの中に入っています。

世界単位で持ち出したい場合は、世界画面の書き出し（↓アイコン）でJSONを保存できます。
これは同じ形式で取り込み直せます。会話は＋メニューから、キャラクターは
Character Card V2 形式で書き出せます。

---

## 補足: このアプリが自動でしないこと

- **AIに時刻を書かせません。** 時間の真実はアプリが持ちます
- **天候をターンごとに変えません。** 日付が変わったときだけ抽選します
- **過去のメッセージは再生成しません。** 分岐に統一しています
- **会話データを端末にキャッシュしません。** サーバのDBが唯一の正です
  （送信前の下書きだけは、誤操作対策で端末に保持します）
